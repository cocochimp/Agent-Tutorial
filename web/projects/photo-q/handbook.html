项目背景：面向中小学拍照搜题与追问讲题场景，解决通用大模型「识题不准、搜不到原题、多轮追问断片、解题步骤编造」四类问题，构建覆盖「识题 → 检索 → 记忆 → 讲解」全链路的垂直领域智能体。

工作内容：

  1. ReAct 规划编排： 将 OCR、公式识别、题库检索、解题生成、相似题推荐封装为 Function Calling 工具，基于 ReAct 做多步推理与工具调度，并用 LangGraph 编排"解析→检索→记忆→生成→校验"状态机（含置信度阈值与 human-in-the-loop）；工具调用准确率 ≥92%。（PS：让系统自己会「识题 → 搜题 → 讲题」：一张作业照片里常有好几道题，识别也可能出错。我把识题、搜题、讲解拆成一个个可单独调用的工具，让系统自己判断先做哪一步、出错了如何重试，减少调错和跳步，工具调用准确率做到 92%。）
  2. 多模态/增强 Query 理解： 拍照经 OCR/公式识别输出 LaTeX，再做上下文改写、题目拆解（一图多题）、HyDE、Step-back 知识点泛化，输出「意图/学科/知识点/年级」结构化字段驱动下游 filter，复杂场景检索解决率提升25%。（PS：先把题读懂，再去搜：解决「一张图混着好几道题」「学生追问『这道题』到底指哪一道」这类情况——先把题目拆清、公式读准、把没说完整的追问补全，复杂场景下正确找到题目的比例提升 25%）
  3. 混合检索与结果精排：搭建语义检索BGE与关键词检索BM25双路并行、融合排序RRF与相关性精排的题库匹配方案，原题命中率提升 18%。（PS：让题搜得到、也搜得准：针对「带公式的数学题经常搜不到原题」，把「按语义搜」和「按关键词搜」两种方式结合，再对结果重新排序、挑出最匹配的原题，原题命中率提升 18%。这一段是重难点，可以改成：稠密向量召回（BGE + HNSW）+ 稀疏 BM25 双路（各 topK=100）经 RRF 融合取 Top 50，BGE-Reranker（Cross-Encoder） 精排至 Top 10，再叠加多维度排序 + MMR 去冗余；粗召回 Recall@100 84%→96%）
  4. 上下文与记忆系统：建设多轮会话短期记忆与学生画像长期记忆，配合上下文动态注入与压缩，多轮追问理解准确率提升 30%，单次会话 Token 成本下降约 70%。（PS：让它记得住上下文，也越用越懂学生：既记得上一轮讲了什么（多轮追问不断片），也逐步记住每个学生的易错知识点（越用越贴合），同时控制每次携带的信息量，多轮追问理解准确率提升 30%，单次对话成本下降约 70%。如何搭建？建设短期会话记忆（多轮指代消解 + 滑动窗口摘要压缩）与长期用户画像记忆（易错/已掌握知识点，向量化存储、检索时作个性化 boost）；设计 token 预算分配与上下文动态注入；多轮追问理解准确率 +30%，Prompt Token 降 40% 且问答质量不降。）
  5. 解题生成与质量保障：以检索内容为唯一依据约束模型输出，引入LaTeX公式校验、事实核查与人工兜底，并建设多学科“金标准”评测集，解题步骤正确率提升至 96%（PS：保证讲得对、不编造：只允许模型依据搜到的真实题目讲解，再加一道公式与答案的核查，拿不准就转人工；并整理了一套覆盖多学科的题目用于验证效果，解题步骤正确率做到 96%。如何实现？以检索/记忆命中内容为唯一数据源，LLM 强制 JSON 结构化输出 + 公式 LaTeX 逐项校验；引入 Fact-Checker（阈值 0.85） + 硬规则/LLM 后过滤，低于阈值触发 Self-Refinement；构建覆盖多学科评测集（金标准 + 禁止错误类型），解题正确率 ≥96%，单次对话 Token 成本降 60%–80%、P99 ≤ 1.2s。）

项目总览 & 30 秒开场

建议背熟的开场：我实习做的是一个面向 K12 的「拍照搜题 Agent」——用户拍一张题目照片，系统要识别题目、从五百万题库里找到最匹配的原题和知识点，再生成分步骤的讲解，并且支持多轮追问。我主要负责把它当成一个「智能体」来搭：从工具编排、多模态识题、检索、上下文与记忆，到最后的解题生成与质量把关这条完整链路。

先建立一个概念：什么是 RAG，为什么拍照搜题非用它不可

RAG（检索增强生成）＝「先检索、再生成」：不让大模型凭记忆直接答，而是先从可信题库里检索出真实原题与知识点，再让模型基于这些材料讲解。拍照搜题场景对正确率零容忍——讲错一步就是教学事故，模型凭记忆很容易编造公式，所以答案必须可溯源、可校验，这正是 RAG 的用武之地。RAG 的两大主力就是后面反复出现的「粗召回（解决召回率，别漏）」和「精排（解决准确率，排准）」。

四个关键词（记住这四个，任何追问都能回到主线）

多模态输入
拍照不是文本：要先做 OCR 与公式识别，把图片变成机器能检索的结构化问题。
检索增强
答案不能靠模型编，必须先从题库检索到真实原题与知识点，再让模型基于它讲解。
记忆增强
多轮追问要记住上一步，长期使用要记住这个学生的易错点，本质都是上下文管理。
生成可控
解题必须可溯源、可校验：唯一数据源 + 公式校验 + 事实核查，低置信度转人工。

面试时先用这段 30 秒讲清「是什么、我做了哪条链路」，再等追问逐层展开。

整体架构与检索漏斗

整条链路可以用一句话概括：把一张照片，一步步收敛成一道可讲解的原题。每一环都是「上一环的输出，下一环的输入」。

拍照→OCR / 公式识别→Query 理解→混合召回→精排 / 去重→记忆注入→解题生成→校验

检索漏斗：为什么层层收敛

核心思想是「用便宜的方法多召回，用贵的方法精挑」。候选数量逐层收敛，越往后用的模型越强、越贵，但处理的候选越少（下面的取值与 RAG 实战文档一致：双路 Top-60、融合 Top-40、精排到个位数）：

500 万题库
  │  ① Query 理解：1 张照片 → 1~3 个子问题（+ 结构化过滤条件）
  ▼
每个子问题并行两路检索：
  ├─ 语义（向量）检索   取前 60
  └─ 关键词（BM25）检索 取前 60
  │  ② 归一化 + 加权融合（或 RRF）去重 → 前 40   （粗召回出口）
  ▼
③ 精排模型（Cross-Encoder）重排 40 条 → 前 10（动态截断：分≥0.6，最多10，至少2）
  │  ④ 多维度排序 + MMR 去冗余 → 前 5
  ▼
⑤ 注入解题上下文：前 3
一句话记忆：60 → 40 → 10 → 5 → 3。粗召回决定系统效果的上限（漏了就再也找不回），精排只能逼近它、无法超越——所以前面宁可多召回，后面再慢慢精挑。

RAG 核心概念（后面各章的理论底座）

这一章把「拍照搜题」用到的检索理论一次讲透，后面工作章节直接引用，不再重复。一句话分工：

1、粗召回解决「召回率（别漏）」
2、精排解决「准确率（排准）」
3、Query 理解在最前面决定「怎么搜」。

一、粗召回：解决召回率问题

北极星：召回侧用双塔（Bi-Encoder）——query 与文档各自离线编码成向量、在线用 ANN 近邻检索，重速度（深度交互太贵，召回阶段付不起）。

核心链路（与实战文档一致）：

输入 Query
  → Filter 过滤（知识/时间范围等结构化元数据，硬筛选，不打分）
  → Query 扩写（语义 ×3 / 关键字 ×3，救回口语化、残缺、歧义）
  → 双路召回：向量(Top-60，余弦∈[0,1]) ＋ BM25(Top-60，分∈[0,20])
  → Min-Max 归一化 → 加权混合 Final = α·sparse + (1-α)·dense（α≈0.3~0.7）
  → 取前 40 送精排
向量召回（BGE + ANN）
匹配语义而非字面，「求导数」能召回「微分运算」；抗同义词、抗改写。弱点：吃不准公式符号、编号、专有名词。
关键字召回（BM25）
基于词频的字面精确匹配：公式符号、题号、专有名词命中极准，快、便宜、可解释。弱点：完全不懂语义，换个说法就漏召。
Filter 结构化过滤
用元数据（学科/年级/权限）做硬筛，缩小候选、更快更准；本质是「确定性关卡」，不参与相关性打分。依赖标签质量。
QA 子切片（泛化召回）
离线为每个文档切片用 LLM 生成 3~5 个「用户可能会问的问题」，每个问题独立编码入库并关联父切片 ID。让「问题 vs 问题」而不是「问题 vs 文档」匹配，召回更准。
HyDE（假设性文档）：先让 LLM 对 query「假想写一段答案/相似题干」，再用这段假想答案去做向量召回——因为「答案 vs 答案」的向量比「问题 vs 答案」更接近。属于 Query 扩写的一种，专治「问法和原文写法差很远」。

二、精排 / 重排：解决准确率问题

北极星：精排侧用交叉编码器（Cross-Encoder）——把 query 和 doc 拼在一起在线逐对打分，重精度（候选量已经很小，付得起）。链路：query + doc[Top-40] → 精/重排 → Top 2~10 → 组装 context → LLM。

多维度排序：相关性只是一维

权威度
维护来源表给每种 source_type 一个 [0,1] 先验权重（官方 1.0 > 内部 wiki 0.8 > 社区 0.5 > 匿名转载 0.2），入库打标、精排查表。
时效性
用衰减因子建模：越新时效分越高，但平滑递减（30 天=1.0、60 天≈0.9、90 天≈0.81），不一票否决稍旧但权威的内容。
质量分
离线预计算 quality = α₁·完整性 + α₂·准确性 + α₃·可读性。
丰富度（MMR）
贪心地每次选「既相关、又和已选不相似」的一条，去冗余（见下）。
动态截断（代替固定 Top-K）：不再死取 Top-5，而是「取 Final 分 ≥ 0.6 的候选，最多 10 条、至少保 2 条」——高置信时多给、低置信时宁缺毋滥。

三、Query 理解：三大块

① 改写与拆解
上下文改写（「那第二问呢」→ 补成完整题）、纠错顺句（OCR「涵数」→「函数」）、问题拆解（一题多问拆成多条子 query）、扩写（HyDE / 同义变体）。
② 问题理解（只决策不检索）
判是哪类题 → 路由到哪个库；判时效态度 → 要不要加时间过滤；判偏精确还是偏语义 → 调融合权重 α。
③ 关键信息提取
把散落属性抽成结构化实体 {年级,科目,知识点,题型} 喂 Filter；时间归一化「去年期末卷」→ 2025-01~02。

四、融合方法之辩：RRF vs 加权归一化（面试会追）

方法怎么算优点短板 / 适用
加权归一化各路分数先 Min-Max 归一化，再 Final=α·sparse+(1-α)·dense保留分数「强弱」信息，可按 query 特性调 α需可靠归一化；min/max 受异常值影响，需调 α
RRF只看排名：score = Σ 1/(k + rank)，k 常取 60无需归一化、对异构分数鲁棒，工程简单丢弃分数强度信息；适合分数不可比/难归一化时
本项目选型：拍照搜题两路分数量纲差异大且波动，优先用 RRF 保稳（鲁棒、少调参）；当需要按「这题偏精确 / 偏语义」动态调侧重时，再切到加权归一化 + 动态 α。两者不是二选一的对错，而是「稳 vs 细」的取舍。

工作一 · Agent 工具编排与流程规划

🎯 真实需求场景：产品提了个需求——「家长拍一张含 3 道题的作业照片，App 要能自动逐题识别、分别讲解」。这件事没法用一条写死的流程搞定：有的题要查公式、有的题要找相似题、识别失败还要重试。于是需要让系统像人一样「自己决定下一步调用哪个工具」，这就是 Agent 编排要解决的问题。
用户输入→模型规划下一步→调用工具→看结果再规划→直到给出答案

我做了什么

工具封装
把 OCR、公式识别、题库检索、解题生成、相似题推荐封装成统一的可调用工具，每个工具的入参出参用固定 Schema 约束。
多步规划（ReAct）
让模型「思考 → 行动 → 观察结果 → 再思考」循环，自主决定调用哪个工具、按什么顺序调。
流程编排（LangGraph）
用状态机把「解析 → 检索 → 记忆 → 生成 → 校验」串起来，关键节点设置置信度阈值和人工兜底。

为什么这么做 + 关键设计

做法为什么参数 / 指标
工具入参出参强制 Schema模型经常传错字段、漏参数，不约束就会调用失败或答非所问。Schema 校验 + 错误重试，工具调用准确率提升至 92%。
强制先检索再作答不强制的话模型会「跳过检索直接编」，这是幻觉的主要来源。检索工具设为必经节点。
用状态机而非一条链识题失败要回退重试、低置信度要转人工——固定链路表达不了这些分支。关键节点置信度阈值 + human-in-the-loop。

面试追问

ReAct 和「写死的流程（workflow）」有什么区别？
写死的 workflow 是固定顺序，适合流程确定的场景；ReAct 让模型每一步看着上一步的结果，自己决定下一步做什么，适合「一图多题、要不要重试、调哪个工具」这种不确定分支。代价是更耗 token、也更难预测，所以我用状态机把边界框住，只在需要判断的节点交给模型。
为什么工具要做 Schema 约束？不约束会怎样？
模型输出是自然语言概率分布，不约束就可能传错类型、漏字段、编造不存在的参数，导致工具调用失败甚至串数据。用固定 Schema + 校验 + 失败重试，能把工具调用准确率显著拉高。
不要说「Agent 就是让大模型自动干活。」
应该说Agent 是「模型做大脑 + 工具做手脚 + 编排框边界」，我负责把工具和编排这层做稳。
不要说「流程我用 if-else 串起来的。」
应该说用状态机编排，把重试、转人工这些分支显式表达出来。

工作二 · 多模态解析与 Query 理解

🎯 真实需求场景：两个真实痛点——① 学生拍完一道题，紧接着追问「这道题第 2 步为什么这么写」，「这道题」到底指哪道？② 一张照片里混着好几道题。如果不先把图片「读懂、拆清、补全」，后面检索再强也白搭，因为送进去的问题本身就是残缺的。
照片→OCR + 公式识别→题目拆解→指代消解 / 补全→关键信息提取→结构化问题

我做了什么（对应 RAG 的 Query 理解三大块）

改写与拆解
一图多题拆成多条子 query；追问做上下文改写与指代消解；OCR 错字纠错顺句；必要时 HyDE 扩写。
问题理解（决策）
判学科题型 → 路由题库；判偏精确/偏语义 → 调融合侧重；判时效 → 要不要加年份过滤。
关键信息提取
抽出 {年级, 科目, 知识点, 题型} 结构化字段，喂给 Filter 硬过滤、喂给精排做加权。

Query 理解的结构化输出（示例）

场景① · 一图三题，第 2 题写着「接上一题的结果继续计算」　Query 理解 / 拆解 + 指代消解
场景
学生拍了一张含 3 道题的作业照片，第 2 题题干是「接上一题的结果，求该数列前 n 项和」——它自己不完整，依赖第 1 题的答案。
处理流程
① 版面切分识别出 3 道题；② 拆成 3 条子 query 各自独立检索；③ 检测到第 2 题含跨题指代「上一题的结果」，不直接检索，先建立题间依赖：把第 1 题的解题结论（如「通项 aₙ=2n-1」）回填进第 2 题题干，补全成「已知 aₙ=2n-1，求前 n 项和 Sₙ」；④ 补全后的完整 query 再走检索与讲解。
关键决策
为什么不把三题拼一起检索？——会互相干扰、谁都搜不准。为什么第 2 题要等第 1 题？——存在数据依赖，需按依赖顺序求解，用一个「题目依赖图 + 结果槽位」来编排（本质是 Agent 编排的一个子图）。
失败兜底
若第 1 题没解出/低置信，第 2 题无法补全 → 不硬编一个假结果，而是提示学生「请把第 1 题也拍清楚」或让学生手动确认上一题答案；指代对象有歧义（有两个「上一题」候选）时，回退为「向学生澄清」。
易踩的坑（语义漂移）：改写不能「过度」。把问题改得太多会偏离原意反而搜错。所以每次改写都带置信度，低于阈值就回退用原始 query；并用「改写前后一致性」做离线评测，防止改写模块偷偷把召回带坏。

面试追问

为什么不直接把图片丢给多模态大模型，让它一步到位？
可以做一版基线，但纯多模态直出有两个问题：一是公式、手写体识别不稳定，二是它「读懂了」不等于「查到了真实原题」，仍会编答案。所以把「识别」和「检索作答」拆开：识别只负责把图片变成可检索的结构化问题，作答交给检索增强来保证可溯源。
追问里的「这道题」你怎么让系统知道指的是哪道？
靠短期会话记忆做指代消解：把最近几轮对话里出现过的题目对象保留下来，追问时把「这道题/上一步」绑定到最近一次讲解的对象上，再补全成完整问题去检索。多个候选有歧义时宁可向学生澄清。
什么是 HyDE？拍照搜题里怎么用？
HyDE 是先让 LLM 对问题「假想写一段答案/相似题干」，再拿这段去做向量召回，因为「答案 vs 答案」的向量比「问题 vs 答案」更接近。拍照搜题里，学生的问法（口语）和题库原题写法差很远时，用 HyDE 生成一段规范题干再检索，能显著提召回。

工作三 · 混合检索与结果精排

🎯 真实需求场景：线上反馈了一个 bug——「一道带根号、绝对值符号的数学题，系统搜出来一堆‘看着像但其实不是’的题，就是找不到那道原题」。排查发现：纯语义检索擅长「意思相近」，但对公式符号、专有名词这种精确匹配不敏感。于是我加了关键词检索来补这一刀（理论见 RAG 核心概念）。
子问题→语义 60+关键词 60→融合 40→精排 10→去冗余 5→注入 3

我做了什么

双路召回
语义（向量）检索懂「换了说法也能找到」，关键词（BM25）检索懂「公式、题号精确匹配」，两路各取 Top-60 并行互补。
融合排序
两路分数不可比，默认用只看排名的 RRF 融合去重取前 40，再按学科/知识点结构化过滤；需要动态调侧重时切加权归一化。
精排 + 去冗余
用 Cross-Encoder（BGE-Reranker）对 40 条逐条精判取前 10，再用 MMR 去掉近似重复题取前 5，注入前 3。
场景② · 换个写法的同一道题　向量召回 vs BM25 谁能命中
场景
学生的问题是「求函数 f(x)=x²+2x+1 在 x=3 处的导数」，而题库里存的是同一道题的另一种写法「已知二次函数 f(x)=(x+1)²，求 f′(3)」。字面几乎不重叠（x²+2x+1 vs (x+1)²、"导数" vs "f′"）。
处理流程
① 向量召回：能理解「x²+2x+1 = (x+1)²」「求导数 ≈ f′」，语义相近，大概率命中，是这题的主力；② BM25：靠字面，"f(x)"、"x=3/f′(3)"这些符号仍有部分重叠，作补充；③ 若配合 HyDE（先假想写出解题式）或 QA 子切片（题库离线已生成「怎么求 f(x)=(x+1)² 的导数」这类问句），命中更稳。
关键决策
这题体现向量召回的价值——跨写法的语义匹配正是 BM25 的盲区；反过来「第 38 页第 3 题」「∮ 符号」这类才是 BM25 的主场。所以必须双路都上，靠融合取长补短。
失败兜底
若 embedding 对「配方/因式分解等价」不敏感导致向量也没召回 → 用 QA 子切片泛化召回补救；仍搜不到则判为「题库无原题」，走「不返回错题，转通用解题模式并明确标注‘未匹配到原题’」，而不是硬塞一个相似题。
场景③ · 粗召回回来 5 条，精排怎么排　Cross-Encoder + 多维度 + MMR
场景
某道题粗召回返回 5 条候选：A、B 是近似重复题（只有数字不同），C 是同一知识点的不同题型（选择题 vs 原填空题），D 是关键词重叠但完全无关的题（都含"函数"但考点不同），E 是真正的原题。
处理流程
① Cross-Encoder 逐条把 query 与候选拼一起打分：E 最高、A/B 次之、C 中等、D 因语义不相关被打低分（这正是精排比粗召回强的地方——D 是关键词骗过了 BM25，精排能识破）；② 多维度加权：E 若来自官方题库再加权威度分；③ MMR 去冗余：A、B 高度相似，只保留其一，避免给模型喂两份重复。
关键决策
最终顺序约为 E > A（或B）> C，D 被过滤、B（与A重复）被 MMR 去掉。C 保留是因为「同知识点异题型」对讲题有价值（可作举一反三），但排在原题之后。λ 取 0.7 偏相关、留一点多样性。
失败兜底
若精排把 D 误判为高分（业务偏移）→ 归因到精排层，注入业务提示词或加难负例重训；若 E 根本没进这 5 条（漏召）→ 不在精排调，回去查粗召回（扩 Top-K / 调融合 / 检查 Filter 是否过紧）。

为什么每层 topK 是这个数

环节取值为什么这么定
每路召回前 60太小（如 20）正确原题可能没进候选，效果上限被锁死；太大后面精排又慢又贵。看 Recall@K 曲线在 50~100 区间收益变平，实战取 60。
融合出口前 40给精排一个「够用又不过量」的候选池；粗召回的目标是「别漏」，精排的目标才是「排准」。
精排出口前 10（动态截断）Cross-Encoder 把问题和候选拼一起联合判断，精度高但很贵。用「分≥0.6、最多10、至少2」动态截断，代替死取 Top-K。
去冗余出口前 5 → 注入 3题库多近似重复题，MMR 兼顾相关性与多样性；注入越多噪声越大、成本越高，Top-3 覆盖大多数原题。
成效：加了关键词检索 + 融合 + 精排后，原题命中率提升 18%，公式类题目「搜不到原题」的问题基本解决。

面试追问

为什么要「向量 + 关键词」两路，只用一路不行吗？
向量检索懂语义、换个说法也能命中（见场景②），但对公式符号、专有名词这种精确 token 不敏感；关键词检索正好相反，擅长精确匹配但不懂近义。两者互补，所以做混合检索再融合。
Cross-Encoder 为什么比向量召回准，却不能拿来扫全库？
向量召回是双塔：query 和 doc 各自编码再算距离，没有交互，快但粗。Cross-Encoder 把 query 和 doc 拼一起送进模型做全程自注意力交互，精度高但每一对都要跑一次前向，很贵，只能处理粗召回筛出来的几十条。
融合你用 RRF 还是加权归一化？怎么选？
默认 RRF——只看排名、无需归一化，对两路量纲不一的分数最鲁棒，少调参。当要按「这题偏精确还是偏语义」动态调侧重时，改用 Min-Max 归一化 + 加权（Final=α·sparse+(1-α)·dense）。取舍是「稳 vs 细」。

工作四 · 解题生成、幻觉治理与质量把关

🎯 真实需求场景：出过一次线上事故——「模型编造了一个不存在的公式，把学生教错了」。教育场景对正确率的容忍度极低，讲错一步就是事故。所以这一环的核心不是「讲得多漂亮」，而是「可溯源、可校验、错了能拦住」。
检索命中内容→约束生成（唯一数据源）→公式校验→事实核查→过关 / 自我修正 / 转人工

我做了什么（治幻觉三板斧）

唯一数据源
解题只能引用检索到的原题与知识点，不许模型自由发挥、凭记忆编。
结构化 + 公式校验
强制模型按固定结构输出（步骤、公式、答案分字段），公式逐项校验 LaTeX 能否正常渲染。
事实核查 + 兜底
对生成结果打置信度，低于阈值触发自我修正重试，仍不过关就转人工，绝不硬输出。

先把幻觉分类，再对症下药

幻觉类型例子主要拦截手段
无中生有编造一个不存在的「定理/公式」唯一数据源约束 + 事实核查（比对检索材料里有没有这条依据）
张冠李戴把别的题的解法套到这道题唯一数据源 + 精排保证注入的是真原题（见工作三场景③）
计算错误推导步骤算错数结构化输出分步 + 代入验算 / 符号计算校验
格式错误LaTeX 渲染失败、字段缺失渲染校验 + Schema 校验，失败即触发重试
场景④ · 讲解里公式渲染失败、还编了个「定理」　Fact-Checker + Self-Refinement
场景
模型生成的解题步骤里：① 有一行 LaTeX \\frac{-b}{2a 少了个花括号，前端渲染失败变乱码；② 结尾还写了「根据韦达差值定理可得…」——这个定理压根不存在。
处理流程
① 格式校验：逐条把 LaTeX 送进渲染器试渲染，捕获到那行失败 → 标记 render_error；② 事实核查：把「韦达差值定理」拿去和检索命中的知识点材料比对，材料里查无此条 → 标记 unsupported_claim，整体置信度被拉到阈值 0.85 以下；③ Self-Refinement：把「哪一行渲染失败、哪句缺依据」作为反馈回灌给模型，要求它只依据材料重写这两处；④ 重试通过校验后放行。
关键决策
为什么阈值定 0.85？——在评测集上扫阈值看「漏放错误 vs 误拦正确」的 PR 曲线，0.85 是「几乎不漏放硬伤、又不过度误拦」的拐点。为什么用 Self-Refinement 而不是直接换答案？——它能在保留正确部分的前提下只修坏的那几处，改动最小。
失败兜底
重试上限（如 2 次）防死循环：重试仍不过关 → 不硬输出，转人工审核 / 回复「这道题我暂时不确定，帮你转给老师」。教育场景宁可不答，也不能答错。

为什么这么做 + 关键设计

做法为什么参数 / 指标
唯一数据源约束幻觉的根源是模型「没检索到也硬答」，锁死数据源就锁死大部分幻觉。只允许引用检索内容。
置信度阈值 + 自我修正低置信度结果直接给用户风险太高，宁可重试或转人工。阈值 0.85（PR 曲线拐点），重试上限 2 次。
硬规则 + 语义后过滤有些错误（格式、明显矛盾）用规则就能拦，不必都靠模型。规则 + 语义双重把关。
建评测集没有评测集的「优化」都是拍脑袋（详见评测体系章）。覆盖多学科，金标准答案 + 禁止错误类型。
成效：解题步骤正确率提升至 96%，配合缓存与上下文动态注入，单次会话 Token 成本下降约 70%。

面试追问

幻觉是怎么产生的？你怎么治？
幻觉主要来自「模型没有依据也硬答」。先把幻觉分类（无中生有 / 张冠李戴 / 计算错 / 格式错），再三板斧：唯一数据源、结构化输出 + 公式校验、事实核查打置信度低于阈值就自我修正或转人工。教育场景宁可不答也不能答错。
Fact-Checker 的置信度阈值怎么定的？
不是拍的。在评测集上扫不同阈值，画「漏放错误率 vs 误拦正确率」的 PR 曲线，取二者平衡的拐点（约 0.85）。阈值调高会拦得更严但误伤正确答案，调低会漏放硬伤，取决于业务对「错答」和「不答」的容忍度。
Self-Refinement 会不会一直重试、卡死？
设重试上限（如 2 次）＋每次都带上「具体哪里错」的结构化反馈。超限仍不过关就转人工或礼貌拒答，绝不无限循环，也绝不硬输出没通过校验的内容。

工作五 · 上下文与记忆系统设计

🎯 真实需求场景：两个需求推动了这块——① 学生会连续追问：「这一步为什么」「换个方法讲」，系统必须记得上一轮讲了什么、当前在讲哪道题；② 学生每天来搜题，产品希望针对他经常错的知识点优先讲得更细、推更贴合的练习。前者是「这一轮记得上一轮」（短期），后者是「越用越懂这个学生」（长期）。

记忆系统的三层结构

上下文与记忆系统
├─ 短期记忆（会话级）
│   ├─ 会话状态：当前题目栈（正在讲哪道）、讲解进度（讲到第几步）
│   ├─ 多轮指代消解：「这一步 / 上一题」→ 绑定题目栈里的对象
│   └─ 滑动窗口 + 摘要压缩：对话过长时旧内容压成摘要，只留最近几轮原文
├─ 长期记忆（用户级 / 跨会话）
│   ├─ 学生画像：知识点掌握度、错题本、常搜学科、偏好难度
│   └─ 去重写入：内容做指纹 + 状态锁，避免同一条记忆重复写
└─ 上下文预算管理
    └─ token 有限，按优先级注入：系统提示 > 当前问题 > 检索原题 > 记忆/画像

三块怎么建（校招够讲的深度）

会话状态（短期）
维护「当前题目栈 + 讲解进度」，让追问能定位到对象；这也是工作二指代消解的数据来源。会话结束即释放。
学生画像（长期）
为每个知识点维护一个掌握度（0~1）：答对/看懂则上调、答错/反复问则下调，并随时间缓慢「遗忘衰减」。再挂一个错题本（记录错题、错因、复习次数）。
预算与回流
画像不是全量塞进上下文，而是按当前题的知识点检索出最相关的几条再注入（画像也当一路「召回」）。历史行为回流成个性化 boost。
掌握度建模（概念级，不必上重模型）：把它理解成一个随行为升降、随时间衰减的分数即可——答对/听懂 → 加分；答错/反复追问同类题 → 减分；长期不碰 → 缓慢回落。面试讲清「怎么更新、拿它干嘛（驱动个性化推荐与讲解详略）」比套公式更重要。
场景⑤ · 一节课连问 5 道一元二次方程　掌握度建模 → 薄弱点识别 → 针对性推荐
场景
学生在一次会话里连续问了 5 道一元二次方程的题，其中 3 道都卡在「判别式 Δ 与根的关系」这一步反复追问。
处理流程
① 每道题讲完，把知识点「一元二次方程-判别式」的掌握度下调（反复追问=信号弱），并写入错题本（错因：判别式符号判断）；② 触发写长期记忆（触发时机：答错 / 同类反复），做去重写入避免 5 条重复；③ 识别出「判别式」为当前薄弱点；④ 下次该生进来或本轮结束时，优先推 2~3 道判别式针对练习，并在讲解时对这一步讲得更细。
关键决策
为什么用「反复追问」而不仅「答错」作信号？——很多学生不提交答案，追问频次是更早的困惑信号。为什么推荐要控量（2~3 道）？——避免一次压太多打击信心；难度按掌握度选「跳一跳够得着」的。
失败兜底
样本太少易误判（偶尔手滑 ≠ 不会）→ 掌握度更新用平滑/多次确认，不因一次波动就打标薄弱；画像与检索解耦：即使画像判断错，也只影响推荐排序的加权，不会把错题当原题注入讲解（正确性仍由工作四的唯一数据源 + 校验兜底）。

面试追问

对话太长、token 要爆了怎么办？为什么用摘要而不是直接截断？
直接截断会丢掉早期关键信息（比如最初那道题）。用滑动窗口保留最近几轮原文，更早内容让模型压成摘要保留要点，既控 token 又不丢关键上下文；摘要失败还有兜底。再配 token 预算按优先级注入。
知识点掌握度你怎么建模、拿它干嘛？
给每个知识点维护一个 0~1 的分：答对/听懂上调、答错/反复追问下调、长期不碰缓慢衰减。它驱动两件事：推荐（优先推薄弱点的针对练习）和讲解详略（薄弱点讲更细）。更新要平滑，避免一次波动就误判。
长期记忆会不会把学生的错误答案当依据、导致讲错？
不会——画像/记忆只影响推荐与加权，不作为解题的数据源。解题的正确性仍由工作四的「唯一数据源 + 公式校验 + 事实核查」保证。两条链路解耦，画像判断错顶多推荐不准，不会讲错题。

检索漏斗逐层拆解：每层为什么这么调

架构章讲了「60 → 40 → 10 → 5 → 3」这条漏斗，这一章回答面试官最爱追的问题——每一层的数字、阈值、参数到底怎么来的。核心永远是：在「效果、延迟、成本」之间做权衡，每个参数都能讲清为什么。

① Query 理解层 —— 为什么放在最前面？

为什么做：拍照题目常有「这道」「上一题」这类指代，或「一图多题」。不理解就直接检索，等于用一句残缺的话去查题库，后面召回再强也救不回来——它是投入产出比最高的一层。
拆解
一张图若含多题 → 拆成 1~3 个子 query，各自独立走检索。
HyDE
先让模型「假设写一个答案 / 相似题干」，再拿这段去做向量召回——「答案 vs 答案」的向量比「问题 vs 答案」更接近。
Step-back
把具体题抽象成知识点（如「一元二次方程求根」），用于知识点召回。
指标：复杂 / 多题场景解决率 +25%。改写要设置信度兜底——低置信度就用原始 query，避免「过度改写」导致语义漂移。

② 粗召回层 —— topK 为什么是 60？

为什么两路一起：向量召回懂「语义相近」（换了说法也能找到），但对精确 token（公式符号、专有名词、题号）不敏感；BM25 正好相反，擅长精确匹配。两者互补，所以做混合召回。

topK 取值会怎样
太小（如 20）正确原题可能根本没进候选，召回率上限被锁死，后面精排再强也无用。
太大（如 500）Reranker 要逐对打分，延迟和成本线性上涨（Cross-Encoder 很贵）。
60（选它）看 Recall@K 曲线：K 在 50~100 区间收益已趋平（边际递减），实战取 60，是「召回率 vs 成本」的平衡点。
融合两法（详见 RAG 核心概念）：默认 RRF（score = Σ 1/(k + rank)，k≈60，只看排名、最鲁棒）；需要按 query 特性动态调侧重时用 Min-Max 归一化 + 加权（Final=α·sparse+(1-α)·dense，α≈0.3~0.7）。融合去重后取 Top 40。
指标：Recall@40 从 84% → 96%（BM25 + QA 子切片 + Query 改写的累计提升）。记住一句话：粗召回决定系统性能上限，精排只能逼近它、无法超越。

③ 精排 / 重排层 —— 为什么 40 → 10？

为什么需要：粗召回的分数「跨路不可比、噪声多」。Cross-Encoder 把 query 和 doc 拼在一起做全程自注意力交互，判断精度远高于粗召回的「各自编码算余弦」，但很贵——不能扫全库，只能扫粗召回出来的 40 条。
  • 延迟预算：Cross-Encoder 单对约几~十几 ms，40 条可批处理并行，整体控制在端到端 P99（≤1.2s）的预算内；这也是「为什么是 40 而不是 500」的硬约束。
  • 动态截断：不死取 Top-K，而是「Final 分 ≥ 0.6、最多 10、至少 2」，高置信多给、低置信宁缺毋滥。
  • 多维度加权：相关性只是一维，再叠加权威度（官方>UGC）、质量分、时效性，避免「相关但低质/过时」排在前面。
指标：原题 Top-1 命中率 +18%，nDCG@10 +0.12（nDCG 衡量「越相关的排越前」，比单纯命中率更能反映排序质量）。

④ 去冗余（MMR）—— 为什么 10 → 5，λ 怎么定？

为什么做：题库里有大量「近似重复题」。若 Top 5 全是同一道题的变体，等于给模型喂了 5 份重复信息，浪费上下文窗口、推高 token 成本。
MMR 每一步选：  argmax [ λ·相关性(d, query) − (1−λ)·max 相似度(d, 已选) ]
λ 取值偏向后果
λ → 1只看相关性退化成普通排序，近似重复题全进来
λ → 0只看多样性为了不重复把相关性也丢了，可能选进偏题
λ ≈ 0.7相关为主、留一点多样在评测集上扫 λ，看「覆盖率 vs 相关性」，0.7 附近最平衡

N 的消融（示意）：注入 Top-3 已覆盖约 9 成正确原题，Top-5 提升有限却明显增 token，Top-8 几乎不再涨——所以精排留 5、注入 3。

⑤ 生成 + 幻觉治理 —— 为什么只注入 Top 3？

为什么不把 5 条全喂进去：上下文越长，成本越高、噪声越多、越容易被无关内容带偏。经评测，Top 3 已覆盖绝大多数正确原题，性价比最高。
唯一数据源
解题只能引用检索到的内容，不许模型自由发挥。
结构化输出
强制 JSON（步骤、公式、答案分字段），公式 LaTeX 逐项校验能否正常渲染。
Fact-Checker
对结果打置信度，阈值 0.85（PR 曲线拐点）——低于就触发 Self-Refinement（重试上限 2 次）或转人工。
指标：解题步骤正确率 ≥ 96%。

⑥ Bad case 归因 —— 出问题先定位在哪一层

面试杀手锏：能按「现象 → 根因层 → 调哪里」定位 bad case，比只会背参数强得多。切忌「哪层出问题都去调精排」。
Bad case 现象根因层调整方向
漏召：正确答案根本没进候选集粗召层回查粗召（扩 Top-K / 调融合权重 / 检查 Filter 是否过紧），别动精排
错排：正确答案在候选里但没进 Top-K精排层提升相关性权重，检查多维特征是否压过了相关性
噪声：Top-K 混入明显不相关的题精排层压低截断 K 或提高分数阈值，加强难负例训练

业务偏移：某类 query 持续「看似相关实则不对」精排层注入业务提示词或领域微调

高频面试追问（点「随机抽题」练手）

Q1：一句话讲清你的项目和你负责的部分。
面向 K12 的拍照搜题 Agent：用户拍题，系统识题、从五百万题库检索原题与知识点、生成分步讲解、支持多轮追问。我负责把它当作一个智能体来搭，覆盖工具编排、多模态识题、混合检索、上下文与记忆、解题生成与质量把关这条完整链路。
Q2：为什么要做成 Agent，而不是一个固定流程？
因为分支太多：一图多题要拆、识别失败要重试、不同题要调不同工具、低置信度要转人工。固定流程表达不了这些动态决策，所以用 ReAct 让模型自主规划，再用状态机把边界框住。
Q3：拍照搜题为什么不能只靠多模态大模型直出？
纯直出有两个硬伤：公式和手写识别不稳定；「读懂了」不等于「查到了真实原题」，仍会编。所以把识别与作答拆开——识别把图片变成可检索的结构化问题，作答交给检索增强保证可溯源。
Q4：完整讲一下这条 RAG 链路，60→40→10→5→3 是什么？
双路各召回 Top-60（向量+BM25）→ 融合去重取 40 → Cross-Encoder 精排取 10（动态截断）→ MMR 去冗余取 5 → 注入 3 条给生成。前面便宜多召回保上限，后面贵模型精挑排准。
Q5：向量召回和 BM25 各解决什么？举个例子。
向量懂语义：「f(x)=x²+2x+1 求导」能召回题库里的「f(x)=(x+1)² 求 f′(3)」；BM25 擅长精确匹配：「第 38 页第 3 题」「∮ 符号」这类。两者互补，用 RRF 融合。
Q6：融合为什么用 RRF？和加权归一化怎么选？
RRF 只看排名、无需归一化，对两路量纲不一的分数最鲁棒、少调参，所以默认用它；当要按 query 偏精确/偏语义动态调侧重时，改用 Min-Max 归一化 + 加权（α）。取舍是「稳 vs 细」。
Q7：Cross-Encoder 为什么准、为什么贵？和双塔啥区别？
双塔（Bi-Encoder）query 和 doc 各自编码再算距离，无交互，快但粗，用于召回；Cross-Encoder 把两者拼一起做全程自注意力交互，精度高但每对都要一次前向，很贵，只能处理粗召回筛出的几十条。
Q8：HyDE、Step-back、QA 子切片分别解决什么？
HyDE：先假想写答案再检索，让「答案 vs 答案」更近；Step-back：把具体题抽象成知识点做泛化召回；QA 子切片：离线为题库切片生成「用户可能会问的问题」入库，让「问题 vs 问题」匹配。三者都是提召回。
Q9：MMR 的 λ 怎么定？topK 每层怎么定？
都靠评测集扫参：λ≈0.7（相关为主、留点多样，看覆盖率 vs 相关性曲线）；每路召回 60（Recall@K 拐点）、融合 40、精排动态截断到个位数、注入 3（覆盖率消融）。核心是「效果 vs 延迟成本」权衡。
Q10：多轮对话太长、token 要爆了怎么办？
滑动窗口保留最近几轮原文 + 旧内容压成摘要（不直接截断，免得丢最初的题），再按 token 预算优先级注入：系统提示 > 当前问题 > 检索原题 > 记忆/画像。
Q11：短期记忆、长期记忆、知识点掌握度是什么关系？
短期是会话级（题目栈+指代消解），解决「记得上一轮」；长期是用户级画像（掌握度+错题本），解决「越用越懂学生」，驱动个性化推荐与讲解详略。掌握度随行为升降、随时间衰减。
Q12：幻觉怎么治？置信度阈值 0.85 怎么来的？
先分类（无中生有/张冠李戴/计算错/格式错），再三板斧：唯一数据源、结构化+公式校验、Fact-Checker 打分。阈值在评测集上扫 PR 曲线取「漏放 vs 误拦」平衡拐点，约 0.85；低于阈值触发 Self-Refinement（上限 2 次）或转人工。
Q13：线上出了 bad case，你怎么定位？
按现象归因到层：漏召→查粗召回（别动精排）；错排/噪声→精排；冗余→调 MMR 的 λ；过时→时效权重；某类持续偏→业务提示词或微调。先定位再调，切忌哪出问题都去动精排。
Q14：你怎么证明优化真的有效？
靠带版本的评测集：分层评（Recall@40/nDCG@10/Top-1/端到端正确率），每改一个参数跑一遍对比同版本，线上 bad case 回流补题但发版冻结版本，保证可复现。

应该说短期会话记忆和长期画像分开，按需检索注入、写入去重、有触发时机。
不要说「模型不会说错，正确率很高。」
应该说用唯一数据源 + 校验 + Fact-Checker 兜底，低置信度宁可转人工。

可以主动反问面试官的问题

  1. 这个岗位偏「智能体应用开发」（搭产品链路），还是偏「算法/数据」（做检索、评测、数据）？我两块都能聊，但想知道侧重点。
  2. 你们的 Agent 更接近固定 workflow 的应用侧，还是通用型 Agent？编排框架是自研还是用 LangGraph 这类？
  3. 线上对「正确率」和「延迟/成本」哪个更敏感？这决定了检索漏斗和模型选型的取舍。

术语速查

术语一句话解释
ReAct让模型「思考→行动→观察→再思考」循环，自主决定调哪个工具。
Function Calling把外部能力封装成带固定入参出参的工具，供模型按需调用。
RAG（检索增强）先检索真实资料，再让模型基于资料作答，减少编造。
Bi-Encoder（双塔）query 和 doc 各自编码成向量再算距离，快，用于召回。
Cross-Encoder（交叉）query 和 doc 拼一起联合打分，准但贵，用于精排。
BM25 / 关键词检索基于词频的精确匹配检索，擅长公式符号、专有名词。
RRF 融合只看排名不看分数的融合法（Σ 1/(k+rank)），解决多路分数不可比。
加权归一化融合各路分数 Min-Max 归一化后按 α 加权，保留分数强弱。
HyDE先让 LLM 假想写答案，再拿它做向量召回（答案 vs 答案更近）。
Step-back把具体题抽象成知识点，做泛化召回。
QA 子切片离线为题库切片生成「可能被问的问题」入库，问题 vs 问题匹配。
MMR相关性与多样性平衡（λ），去掉近似重复结果。
nDCG@K按位置加权的相关性得分，衡量「越相关越靠前」的排序质量。
指代消解把「这道题」「上一步」还原成它具体指的对象。
Fact-Checker / Self-Refinement对结果打置信度，低于阈值就自我修正重试或转人工，不硬输出。
