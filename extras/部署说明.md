# 可选部署与训练

Redis用于替换默认热点缓存，vLLM用于本地模型推理，LoRA脚本用于训练适配器。以上模块均为可选扩展，基础服务可独立运行。

## Redis

需要先安装并启动 Docker Desktop，使用 Linux 容器。在项目根目录执行：

```powershell
docker compose -f extras/compose.yaml up -d redis
```

修改 `project_config.json` 的 `cache.backend` 为 `redis`，地址保持 `redis://127.0.0.1:6379/0`。重启服务后，`estate_agent/storage.py:Cache` 使用 `redis-py` 的 GET/SETEX 读写；缓存键包含用户、角色、地区、文档版本、检索参数和Prompt版本。Redis连接失败时返回错误，不自动切换缓存后端。

检查：`docker compose -f extras/compose.yaml exec redis redis-cli DBSIZE`。恢复默认可把 backend 改回 `sqlite`。任务检查点仍使用SQLite保证可靠落盘。Redis服务器联调尚未完成。

## vLLM 本地模型服务

适用 Linux / WSL2 + NVIDIA 容器环境。准备支持工具调用的 Qwen3 Instruct 类模型权重。部署前自行按官方兼容矩阵确认CUDA、显存及模型架构。

```powershell
$env:BASE_MODEL_DIR = 'E:/models/base-model'
docker compose -f extras/compose.yaml --profile gpu up -d vllm
```

compose默认使用 `hermes` 工具解析器，针对Qwen类模板；更换模型时必须按该模型改解析器及chat template。`latest` 是部署模板，实际生产请固定验证过的镜像摘要。该配置尚未完成本地GPU部署验证。

然后把根目录模型配置改成：

```json
{"base_url":"http://127.0.0.1:8000/v1","model":"estate-local","api_key":""}
```

本地服务允许空Key；外部服务应按部署要求配置鉴权。适配器部署可为容器挂载LoRA目录，并按官方文档添加 `--enable-lora --lora-modules estate-adapter=/adapter`；客户端model使用 `estate-adapter`。随机微型GPT2烟雾训练产物不适合放进这个Qwen服务。

## LoRA/SFT

```powershell
.venv\Scripts\python.exe -m pip install -r extras/requirements-training.txt
.venv\Scripts\python.exe -X utf8 extras/train_lora.py --smoke
```

smoke模式随机初始化微型GPT2，用5条训练、1条验证样例完成12步CPU更新，保存LoRA，再按相同基础权重重新加载。训练代码使用PEFT `get_peft_model`，只更新LoRA参数；user/system前缀被mask，loss只计算assistant答案。

领域模型训练命令：

```powershell
.venv\Scripts\python.exe -X utf8 extras/train_lora.py --model E:/models/基础模型 --data E:/datasets/train.jsonl --steps 100 --output output/domain_adapter
```

训练脚本采用单样本优化循环，暂不支持分布式训练或QLoRA。领域训练需准备足够的数据、按来源划分训练/验证/测试集并确认显存预算。`sft_examples.jsonl`用于流程验证，业务效果需通过独立Agent评测确认。
