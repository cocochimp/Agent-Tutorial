## 1. 背景与意图（Intent & Why）

当前项目是一个完整的 "房产经营分析 Agent" 演示系统（LangGraph StateGraph + FastAPI + 前端工作台），并配套一份《贝壳找房 AI 经营分析 Agent 实习复盘手册》（HTML，128KB、22 章节），内容完整 —— 覆盖工作一～六（意图理解、企业 RAG、Tool Calling 与智能查数、Agent 规划与工作流、Context 与 Memory、幻觉治理与结果校验）、工程化、评测体系、完整 Trace、面试追问等，且每个工作项有真实业务场景、问题、方案与量化指标。

**教学痛点**：手册内容已经是很好的 "课件素材"，但**缺少教学流程**—— 学员拿到一份大文档，不知道从哪看起、每个工作项到底对应系统的哪些节点、输入输出是什么、代码怎么写的。纯文档学习掌握效果不佳。

**本次改造目标**：把现有项目工作台重构为**以 "实习工作项" 为学习单位的教学网站**。学员打开即见**四象限学习视图**：左上 = 工作项选择与说明，右上 = 该工作项全链路节点图，左下 = 工作项内容介绍（融合手册文案），右下 = 真实界面对应节点的输入输出与实例代码。学员按 "工作项 → 全链路 → 逐步学习 → 对照真实输入输出与代码" 的动线自学，并能**导出 HTML** 自己做定制修改。

## 2. 目标（Goals）



1. **默认视图**：学员打开网站（登录后）默认进入 "实现教程" 的四象限学习视图，无需运行任何分析即可学习。

2. **以工作项为单位组织学习**：工作项清单按手册的工作一～六组织（意图理解、企业知识库 RAG、Tool Calling 与智能查数、Agent 规划与工作流、Context 与 Memory、幻觉治理与结果校验），另设补充工作项（工程化 / 评测）。

3. **四象限学习视图**：

* 左上角：工作项选择器 + 工作项一句话说明（可切换）。

* 右上角：该工作项涉及的**全链路节点图**—— 可视化展示 "这个工作项下面有几个节点、分别是什么、每个节点的内容介绍"；**点节点可跳转到该步骤**。

* 左下角：工作项内容介绍（参考 HTML 手册文案：业务场景 → 遇到的问题 → 我做了什么 → 为什么这样选 → 结果指标）。

* 右下角：结合真实情况辅助学习 —— 对应真实界面上高亮的节点 + **输入输出示例（Trace 即输入输出）** + **实例代码**（复用现有源码快照）。**没有输入输出 / 实例代码的节点可以不展示。**

1. **两个 Tab 的信息架构**：

* Tab1「实现教程」= 四象限学习视图（融合 HTML 手册内容），支持**导出 HTML**。

* Tab2「高频面试题」= 常见面试官问题，**按工作项分类 + 工作项之外的汇总问题**，支持**随机抽题练习**，支持**导出 HTML**；题库独立成数据文件，便于后续根据学员真实面试录音 / 视频持续优化。

1. **登录保留为真实登录校验**：项目后续要发布上线，只允许学员进入 —— 账号密码由老师（用户）**发放给学员**，服务端校验通过才能进入；**账号密码不默认展示、需要手动输入**（不做多角色权限体系，但必须服务端校验、禁止未授权访问）。

2. **移除运行功能**：去掉提交经营问题、跑分析、历史任务、工单收件箱、能力对照说明书、API 文档等入口；只保留两个 Tab。

3. **可大胆重构**：项目可大胆修改、大胆重构，最终达成教学目的即可。

## 3. 非目标（Non-Goals）



* 不做多角色权限体系（所有学员登录后看到同一教学视图；登录只做 "是否是被发放账号的学员" 这一道门禁）。

* 不做真实 LangGraph 在线运行 / SSE 流式分析（移除分析助手、运行分析、取消任务等交互）。

* 不保留历史任务、工单收件箱、能力对照说明书入口（可隐藏或移除）。

* 不要求学员配置 API Key / 模型即可学习（教学页数据静态化，来自预置数据文件与样例）。

* 面试题库首版不追求完整；结构上支持后续按真实面试反馈持续增删改（数据文件独立、字段预留频次 / 状态标记）。

## 4. 反目标（Anti-Goals）



* 不让学员在打开页面前必须 "跑一遍分析" 才能看到内容。

* 不把教学页面做成依赖运行时状态 / 实时后端结果的形态。

* 不引入对学员理解无帮助的复杂操作（角色选择、决策模式、检索链路开关、会话 ID、知识图谱开关等一律移除）。

* 不把 "导出 HTML" 做成只能看不能改的静态快照 —— 导出物必须支持学员自定义修改（可编辑）。

## 5. 约束（Constraints）



* **复用现有资产**（不要重写一切）：


  * LangGraph 执行图：`estate_agent/diagram.py` 生成 SVG，接口 `/api/graph` 返回 `{svg, mermaid}`；教学视图的右上角节点图可基于现有图数据静态渲染 / 裁剪为 "当前工作项相关节点"。

  * 实现教程数据：`web/tutorial-data.json`（11 lessons + 20 个源码文件快照，含 path/start/end/note）—— 右下角**实例代码**直接复用此数据源；`web/learning.js` 的源码阅读器（词法着色、行号、复制代码）可复用或抽取。

  * 节点→主题映射：`learning.js` 已有 `topics`（understand→intent、agent\_node→graph、sql 工具→sql、rag\_search→rag、generate\_report→report、finish→memory、恢复类→recovery、扩展类→extensions），是 "工作项↔节点↔教程内容" 映射的现成基础。

  * HTML 手册：`/Users/Doc/review/贝壳找房_AI经营分析Agent_实习复盘手册.html`—— 左下角内容介绍文案来源（工作一～六章节）。

  * 现有样式体系：`web/style.css`（37KB，深蓝工作台风格），可继承并扩展。

* **导出 HTML 的形态**：参考手册本身的实现 —— 导出物是**单文件自包含可编辑 HTML**（内联 CSS/JS，正文 contenteditable，支持点击修改、Ctrl+S 保存草稿、一键生成独立新文件）。这是 "学员导出后自己做定制修改" 的关键机制，必须实现。

* 界面语言：中文。

* 工作项清单（本设计采用）：工作一～六（手册正文标题）+ 补充项 "工程化与评测"。理由：手册正文即按工作一～六组织内容介绍，文案可逐章复用。

## 6. 已决定的部分（How，用户逐条拍板）

以下为用户在多轮 brainstorming 中逐条确认的决策，实现时不得再推翻：



1. **默认打开 = 四象限学习视图**；学习动线：进入工作项 → 先看右上角整体有哪些节点 / 核心概念 → 顺着左下角内容介绍一步步学 → 右下角对照真实输入输出与实例代码 → 卡住时点节点跳转到对应步骤。

2. **信息架构 = 两个 Tab**：`实现教程`（四象限视图）+ `高频面试题`（随机抽题练习）。不再有 "分析工作台" 独立入口。

3. **左下角内容介绍**：参考 HTML 手册文案（业务场景 / 遇到的问题 / 我做了什么 / 为什么 / 结果指标等结构）。

4. **右下角**：节点输入输出示例（Trace 即输入输出）+ 实例代码；**某节点没有输入输出 / 实例代码等内容的，可以不展示**；右下角目的是结合真实情况辅助学习。

5. **实现教程要支持导出 HTML**；**高频面试题也要支持导出 HTML**。

6. **高频面试题**：按工作项分类 + 工作项之外的汇总问题；支持随机抽题练习；题库独立数据文件，后续按学员真实面试录音 / 视频持续优化（首版不追求完整）。

7. **登录**：真实登录校验（非演示假登录）——**项目要发布上线、只允许学员进入**，账号密码由老师发放给学员；服务端校验通过才进入；**登录框不默认展示账号密码、需手动输入**。

8. **移除**：提交经营问题、跑分析（含分析助手、运行按钮、取消、SSE 流）。

9. **项目可大胆修改、大胆重构**，最终达成教学目的。

## 7. 数据设计

### 7.1 工作项定义（建议新建 `web/work-items.json`）

结构示意（实现时可调整）：



```
{
  "version": 1,
  "workItems": [
    {
      "id": "work-1",
      "title": "工作一 · 意图理解与结构化输出",
      "short": "意图理解",
      "summary": "一句话说明：把自然语言问题解析为结构化任务参数，并完成权限硬校验。",
      "nodes": ["understand", "clarify"],
      "contentRef": {"manualChapter": "工作一 · 意图理解与结构化输出"},
      "intro": { "scene": "...", "problem": "...", "action": "...", "why": "...", "result": "..." },
      "io": [ { "node": "understand", "input": {}, "output": {}, "note": "..." } ],
      "codeRefs": [ { "path": "estate_agent/intent.py", "start": 1, "end": 30, "note": "..." } ]
    }
  ]
}
```



* `nodes`：该工作项涉及的真实 LangGraph 节点名（与 `app.js` 的 `labels`、`diagram.py` 的节点一致），用于右上角节点图与高亮、右下角 IO 与代码联动。

* `contentRef` / `intro`：左下角内容介绍（文案从手册对应章节提炼）。

* `io`：右下角输入输出示例（Trace 样例，静态预置）。

* `codeRefs`：右下角实例代码（引用 `tutorial-data.json` 的 files 快照，用 path/start/end 指向，不必重复存源码）。

**工作项↔节点映射建议**（实现时以实际图为准核对）：



* 工作一・意图理解 → `understand`（+ `clarify`）

* 工作二・企业知识库 RAG → `rag_search`

* 工作三・Tool Calling 与智能查数 → `agent_node`（工具决策）+ `schema_retrieval` + `query_sql` + `calculate` + `analyze`

* 工作四・Agent 规划与工作流 → `agent_node`（规划 / 条件路由）+ `checkpoint_gate` + `retry_node`

* 工作五・Context 与 Memory → `understand`（context 装配）+ `finish`（记忆持久化）+ storage 相关

* 工作六・幻觉治理与结果校验 → `generate_report` + `validate` + `human_approval`

* 补充・工程化与评测 → 评测体系 / 测试相关主题（可复用 `evaluation` 教程主题，不强制对应图节点）

### 7.2 面试题库（新建 `web/interview-questions.json`）



```
{
  "version": 1,
  "categories": ["intent", "rag", "sql", "agent", "memory", "hallucination", "general"],
  "questions": [
    { "id": "q-001", "category": "intent", "question": "...", "tips": "...", "answer": "...", "weight": 3, "status": "active" }
  ]
}
```



* `category`：按工作项分类 + `general`（工作项之外的汇总问题，如项目定位、30 秒开场、工程化、简历、易错点等）。

* `tips`：提示要点（学员先自答再对照）；`answer`：参考回答（从手册 "面试追问 / 场景化面试法" 章节提炼）。

* `weight`：频次 / 重要度标记（后续根据真实面试录音优化时调整）；`status`：active/draft，便于持续运营。

### 7.3 输入输出示例（Trace 样例）



* 静态预置在 `work-items.json` 的 `io` 字段（每个工作项取 1\~3 个关键节点的真实输入输出样例，可从手册 "完整 Trace" 章节或代码注释 / 示例运行结果提炼）。

* 与现有 `runtime.py` 的 trace 字段结构一致：`{step, input, output, reason, status, latency_ms}`。

## 8. 界面与交互设计

### 8.1 整体布局



* 保留现有左侧导航结构但**只保留两个 Tab**：`实现教程`（默认 active）、`高频面试题`。移除历史任务、工单收件箱、能力对照说明书、API 文档入口。

* 页头 / 面包屑随 Tab 切换：`工作空间 / 实现教程` 或 `工作空间 / 高频面试题`。

### 8.2 实现教程 Tab（四象限学习视图）



* **左上角：工作项面板**—— 工作项列表（工作一～六 + 补充项），点击切换；顶部显示当前工作项的一句话说明。

* **右上角：全链路节点图**—— 该工作项涉及的节点以图 / 链形式可视化（节点卡片：节点名 + 一句话内容介绍），展示 "这个工作项下面有几个节点、分别是什么"；每个节点可点击 → 跳转到该步骤（联动右下角展示对应 IO 与代码，或锚点滚动到学习路径对应位置）。

* **左下角：内容介绍**—— 按手册文案结构展示（业务场景 / 遇到的问题 / 我做了什么 / 为什么这样选 / 结果指标），可折叠、可滚动。

* **右下角：真实对照**—— 当前选中节点的输入输出示例（JSON）+ 实例代码（源码快照、行号、复制按钮）；无内容的节点显示为空 / 提示可省略展示。

* 四个面板联动：切换工作项 → 右上角节点图重绘、左下角内容更新、右下角默认展示该工作项第一个节点；点击节点 → 右下角切换为该节点的 IO 与代码。

### 8.3 高频面试题 Tab



* **分类浏览**：左侧或顶部按分类（工作项 + 汇总）筛选。

* **随机抽题练习**：一键随机抽题 → 显示题目 → 学员先自答（可展开提示 tips）→ 再展开参考回答 answer 对照。

* **导出 HTML**：将当前分类（或全部）题目导出为单文件可编辑 HTML（含问题、提示、参考回答，contenteditable 可改）。

### 8.4 导出 HTML



* 实现教程：导出**当前工作项**的完整学习页（四象限内容 + 节点图 + 内容介绍 + IO + 代码）为独立单文件 HTML，自包含（内联 CSS/JS），正文可编辑，支持点击修改、Ctrl+S 保存草稿、生成独立新文件。

* 高频面试题：导出当前筛选结果（分类或全部）为单文件可编辑 HTML。

* 实现参考：手册本身的 "可编辑 HTML" 机制（contenteditable + 保存草稿 + 生成新文件）。

## 10. 验收标准（Acceptance Criteria）



1. 打开网站 → 登录卡（账号密码输入框默认空白、不展示密码提示）→ 输入老师发放的学员账号密码 → 服务端校验通过 → 进入默认 "实现教程" 四象限学习视图；**未授权账号无法进入**。

2. 左上角可切换工作一～六 + 补充项；切换后右上角节点图、左下角内容介绍、右下角 IO / 代码同步更新。

3. 右上角节点图清晰展示该工作项包含的节点数量与每个节点的内容介绍；点击节点可跳转到对应步骤（右下角联动）。

4. 右下角展示所选节点的输入输出示例与实例代码（复用源码快照）；无内容的节点可省略展示。

5. 无任何 "提交经营问题 / 运行分析" 交互；导航只有两个 Tab。

6. 「实现教程」页可导出当前工作项为单文件可编辑 HTML（可打开、可修改、可保存）。

7. 「高频面试题」Tab 可按分类浏览、随机抽题练习（题目→提示→参考回答），并可导出为可编辑 HTML。

8. 项目可正常启动（`./.venv/bin/python -X utf8 launch.py`），页面无控制台报错，`tests/` 不受影响或按需适配。
