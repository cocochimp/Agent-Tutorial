# 双角色账号体系 + 加密子账号设计文档

日期：2026-10-12

## 意图与 Why

教学站已上线 GitHub Pages（纯静态），目前只有单一写死账号 `chaoyang / demo-chaoyang`。用户要对外分发学员账号，核心诉求：

1. **双角色**：主账号 = 超管（永不过期），子账号 = 学员（自创建日起 2 个月过期）。
2. **创建入口**：主账号登录后，右上角增加「创建子账号」按钮（原 p1 中的「子帐号申请」位）。
3. **安全分发**：创建时账号密码一次性展示给主账号；系统只保存**加密凭证**（防站点被扒后明文泄露）；主账号拿凭证去分配学员。

## 技术约束（已与用户确认）

线上为 GitHub Pages 纯静态，前端**没有服务端写入能力**。用户拍板：**加密数据文件随站点发布**——
主账号创建子账号 → 前端生成数据文件（`sub-accounts.json`，仅含不可逆哈希）→ 导出 → 用户放入项目 `web/` 目录 push 部署 → 全网学员在线登录时前端拉取该文件校验。

## 目标 / 非目标

**目标**
- 主账号（超管）登录：`chaoyang / demo-chaoyang`（沿用），永不过期，登录后可见「创建子账号」。
- 子账号：随机生成账号 + 密码，**支持批量创建 1~10 个**；创建时一次性明文展示全部账号；系统仅存不可逆校验 hash；自创建日 +60 天过期，过期登录被拒。
- 学员登录：前端比对 `sub-accounts.json` 中的 hash + 有效期。
- 导出：可导出包含全部子账号哈希数据的 `sub-accounts.json`。
- **无任何可回溯凭证**：系统不保存明文、不保存 RSA 密文、不提供解密/找回能力；学员忘密码 = 删除旧账号 + 重新创建（防止黑客盗刷）。

**非目标（YAGNI）**
- 子账号续期/删除/修改（删旧建新由重新创建覆盖）。
- 找回/解密/私钥体系（用户明确不要可回溯逻辑）。
- 主账号密码修改。
- 后端 API 账号体系（后续有服务器时再议）。

## 数据设计

`web/sub-accounts.json`（随站点发布；`/static/` 挂载后 URL 为 `static/sub-accounts.json`）：

```json
{
  "version": 2,
  "algorithm": "SHA-256(salt:account:password)",
  "accounts": [
    {
      "id": "stu-20261012-001",
      "note": "学员备注（昵称/批次，可空）",
      "createdAt": "2026-10-12T14:00:00+08:00",
      "expiresAt": "2026-12-11T14:00:00+08:00",
      "hash": "sha256$<salt>$<hex>"
    }
  ]
}
```

- `hash = SHA-256(salt + ':' + account + ':' + password)`：学员登录校验用，**不可逆**。
- **不存明文、不存密文、无公钥/私钥**：系统内不存在任何能把账号密码还原出来的凭证；创建时一次性明文展示后即不可回溯。
- 主账号不在该文件中（写死在前端常量，永不过期）。

## 安全说明（如实告知用户）

- 登录校验层：前端比对 hash。被扒者拿到 hash 无法逆推密码（随机生成的密码强度高，爆破不可行）。
- **无回溯凭证**：数据文件与前端代码中不存在任何可还原明文的材料；即使站点被完整扒取，也无法盗刷出任何学员账号密码。学员忘密码只能由主账号删除旧账号并重新创建。
- 局限：纯前端方案无法做到防爆破限流、服务端审计等能力；若未来需要，数据格式已留 version 兼容位，可平滑引入后端。

## 交互设计

### 登录
- 未登录：居中登录卡（现状不变）。
- 输入账号密码：
  - `chaoyang` 匹配 → 主账号登录（永不过期），右上角显示「创建子账号」。
  - 其他 → 拉取 `static/sub-accounts.json`，按账号查 hash 比对 + 校验 `expiresAt > now`；过期提示「账号已过期，请联系管理员」。
  - `sub-accounts.json` 拉取失败时：仅主账号可登录，子账号提示「账号服务暂不可用」。

### 主账号 → 创建子账号
- 面板（弹窗）两块：
  1. **批量创建**：选择数量 **1~10**（步进器）→ 点击生成 → 一次性展示全部随机账号 + 密码（明文列表 + 逐条复制/一键全复制按钮）→ 写入草稿区。展示后系统即不可回溯。
  2. **草稿区 + 导出**：列出本次创建的账号（仅展示 id/备注/有效期，明文已不可再见）→「导出 sub-accounts.json」→ 合并站点已发布文件 + 草稿 → 下载。提示用户放入项目 `web/` 目录并 push 部署，学员即可登录。
- **无密钥管理、无解密工具**（用户明确不要可回溯逻辑）。

### 本地与 Pages 一致
- 本地 FastAPI（`/api/session` 存在）与 Pages 走同一套前端逻辑：检测到后端时仍可用子账号体系（数据文件读取走 `static/sub-accounts.json` 相对路径，两处一致）；后端 `/api/login` 不再作为子账号登录入口（保留主账号兼容即可，或直接统一前端校验——见计划）。
